# PROJECT HUB 개발 로드맵

## 1. 진행 원칙

PROJECT HUB는 기능을 단계별로 완성하며 각 단계의 테스트 게이트를 모두 통과한 뒤에만 다음 단계로 진행한다. 일정은 팀 규모와 인프라 결정에 따라 조정하되 단계 순서와 품질 기준은 유지한다.

공통 완료 조건:

- 요구사항과 수용 기준이 코드와 일치한다.
- 사용자 UI 문구가 한국어로 완성되어 있다.
- 타입 검사, 단위 테스트, 통합 테스트, 관련 E2E 테스트가 통과한다.
- 허용·거부 권한 테스트가 모두 통과한다.
- 로딩, 빈 상태, 오류 상태가 구현되어 있다.
- 접근성 기본 점검과 반응형 확인을 마쳤다.
- 마이그레이션, 환경변수 예시, 운영 문서가 갱신되어 있다.
- 심각도 높음 이상의 알려진 결함이 없다.

## 7. 단계 4 — 공유 파일함

현재 구현 상태: 공유 파일함을 Google Drive 전용으로 전환하고 개인 드라이브와 Google Workspace 공유 드라이브 조회, 내부 경로 탐색, 폴더 바로가기 해석, 검색, 다중 드래그 앤 드롭 업로드, 폴더 생성, 파일 미리보기·다운로드·이동, 이름 변경, 휴지통 이동과 명시적인 Google 편집기 열기를 구현했다. 최초 OAuth 승인 뒤 비민감 승인 플래그가 있는 브라우저에서 자동 재연결을 시도하며 로컬 예시 파일은 기본 경로에서 제거했다. 운영 OAuth 앱 검증, 실제 계정 E2E, 프로젝트 멤버십과 Google 권한의 연결 정책은 단계 완료 전 후속 범위다.

### 범위

- 개인 드라이브와 Google Workspace 공유 드라이브 탐색
- Google Drive 재개 가능 업로드 API 기반 직접 업로드
- Google Drive 파일 메타데이터와 실제 계정 권한 반영
- 폴더·파일 생성, 이름 변경, Google Drive 휴지통 이동
- 목록/격자 보기, 정렬, 파일명 검색
- Google Drive 웹 미리보기와 원본 열기
- Google OAuth 범위와 공유 드라이브 권한 검증
- 만료 액세스 토큰 재연결 안내

### 테스트 게이트

- Google OAuth 승인·거부·만료·재연결 통합 테스트 통과
- 개인 드라이브와 공유 드라이브 목록 범위 분리 확인
- 공유 드라이브의 읽기·쓰기 기능 제한 반영 확인
- Google Drive API 오류와 부분 업로드 실패 처리 확인
- 실제 Google 테스트 계정 기반 생성·업로드·이름 변경·휴지통 E2E 통과

## 10. 단계 7 — 기본 전자결재

현재 구현 상태: 예시·브라우저 로컬 결재 데이터를 제거하고 실제 PostgreSQL 결재 문서, 순차 결재 상태 머신, 알림·감사 로그와 웹 화면을 연결했다. 결재선 작성과 결재 문서 작성을 분리했으며 프로젝트 참여자로 구성한 개인 소유 결재선 템플릿을 저장·수정·삭제하고 새 기안에 재사용할 수 있다. 첨부는 선택 사항이며 첨부한 문서는 상신 시 파일 버전·객체 키·SHA-256 해시를 불변 리비전에 고정한다.

### 범위

- 결재 문서 초안 작성과 첨부
- 순차 결재선 지정
- 순차 결재선 템플릿 생성·수정·삭제와 기안 시 재사용
- 상신, 승인, 반려, 첫 승인 전 회수
- 상신 시 특정 파일 버전·객체 키·SHA-256 해시를 불변 리비전에 고정
- 반려·회수 후 수정과 새 리비전 재상신, 이전 리비전 보존
- 내 결재 대기·상신 문서 목록
- 결재 상태 머신과 변경 불가능한 처리 이력
- 알림, 감사 로그, 대시보드 집계

### 테스트 게이트

- 모든 유효·무효 상태 전이 단위 테스트 통과
- 현재 순번이 아닌 결재자의 처리 요청 차단
- 동시 승인 요청 중 하나만 성공하도록 경합 테스트 통과
- 결재 중 문서와 결재선 수정 차단
- 반려 사유 필수 및 회수 조건 확인
- 작성→상신→순차 승인/반려 E2E 통과

### 명시적 제외

- 병렬 결재, 합의, 위임, 대결
- 인증서 기반 전자서명과 법적 서명 검증

## 12. MVP 이후 확장 로드맵
