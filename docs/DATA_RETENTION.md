# 데이터 보존·삭제 및 백업 정책

## 1. 보존 기준

| 데이터 | 기본 보존 | 삭제·예외 |
| --- | --- | --- |
| 승인 대기·거절 계정 | 결정 후 30일 | 분쟁 또는 보안 조사 시 접근 제한 후 별도 보존 |
| 활성 계정·멤버십 | 이용/계약 기간 | 탈퇴·계약 종료 요청 후 30일 내 비식별 또는 삭제 |
| 소프트 삭제 이슈·댓글 | 30일 | 관리자 복구 기간 후 영구 삭제 |
| 임시 업로드 | 준비 후 24시간 | 완료 확인되지 않은 객체와 레코드를 멱등 정리 |
| 운영 접근 로그 | 90일 | 보안 사건 관련 로그는 사건 종료 후 1년 |
| 결재·감사 이력 | 프로젝트 종료 후 1년 | 법령·계약이 더 긴 기간을 정하면 그 기간 적용 |
| 백업 | 일간 30일, 월간 12개월 | 암호화 저장 후 만료 시 안전 삭제 |

보존 기간은 법무·계약 담당자의 최종 확인을 받아 조직 정책으로 확정한다. 확정 전에는 자동 영구 삭제를 활성화하지 않고 삭제 후보 보고서를 검토한다.

## 2. 백업

`scripts/backup.ps1`은 PostgreSQL 사용자 정의 형식 덤프, 파일 메타데이터 CSV, S3 객체 목록과 SHA-256 매니페스트를 같은 백업 디렉터리에 생성한다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/backup.ps1
```

운영에서는 백업을 운영 계정과 분리된 저장소에 암호화하고, 최소 권한 서비스 계정과 변경 불가 보존을 적용한다. 백업 성공 알림만으로 복구 가능성을 판단하지 않는다.

## 3. 복구 리허설

복구는 운영 DB가 아닌 고유 이름의 임시 DB에 수행한다. 스크립트는 복원된 사용자·프로젝트·감사 로그 테이블을 조회하고, `AVAILABLE` 파일 메타데이터가 객체 매니페스트에 모두 존재하는지 확인한 뒤 임시 DB를 제거한다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/restore-rehearsal.ps1 -BackupDirectory artifacts/backups/<시각>
```

성공 증적에는 백업 시각, SHA-256, 복구 시작·종료, DB 행 수, 파일 대조 건수와 누락 건수를 남긴다. 누락이 한 건이라도 있으면 출시를 차단한다.

## 4. 삭제 요청

1. 요청자의 신원과 대상 범위를 확인한다.
2. 법령·계약·감사 보존 예외를 확인한다.
3. 활성 DB, 객체 저장소, Google Drive 연결, 검색/캐시와 백업의 처리 계획을 작성한다.
4. 온라인 데이터는 30일 이내 삭제 또는 비식별 처리하고 결과를 기록한다.
5. 백업 데이터는 만료 시점에 제거하며 복원 시 삭제 목록을 다시 적용한다.
