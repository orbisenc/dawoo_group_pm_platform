# 스테이징 사용자 수용 테스트(UAT)

## 1. 실행 조건

- 운영 데이터가 아닌 전용 스테이징 조직·프로젝트·Google 테스트 계정을 사용한다.
- 시행사 관리자, PM, 참여자, 결재자, 읽기 전용 사용자 역할을 각각 준비한다.
- `ENABLE_DEV_AUTH=false`이며 운영과 동일한 CORS, 비공개 S3, Redis와 PostgreSQL 구성을 사용한다.
- 테스트 전 백업과 테스트 후 데이터 폐기 책임자를 지정한다.

## 2. 필수 시나리오

| ID | 시나리오 | 기대 결과 | 결과/증적 |
| --- | --- | --- | --- |
| UAT-01 | 관리자가 프로젝트 생성 후 외부 조직 사용자 초대 | 초대 사용자가 승인 후 해당 프로젝트만 봄 | 미실행 |
| UAT-02 | 사진 첨부 이슈 작성과 다른 사용자 댓글 | 첨부·댓글·알림·감사 기록 생성 | 미실행 |
| UAT-03 | Google Drive 폴더·파일·새 버전 업로드 | 재조회·미리보기·권한이 정상 | 로컬 S3 기술 리허설 통과, Google 사용자 UAT 미실행 |
| UAT-04 | 일정 생성 후 대시보드 확인 | 동일 프로젝트 일정이 표시됨 | 미실행 |
| UAT-05 | 데모 3D 회전·이동·확대·초기화 | 오류 없이 조작되고 데모 고지가 보임 | 미실행 |
| UAT-06 | 결재 상신 후 순차 승인과 반려·재상신 | 현재 결재자만 처리하고 이력 보존 | 미실행 |
| UAT-07 | 다른 프로젝트 URL/API/파일 ID 직접 접근 | 403 또는 404, 데이터 미노출 | 미실행 |
| UAT-08 | Google 토큰 만료·연결 취소·재연결 | 안전한 한국어 안내 후 재연결 성공 | 미실행 |
| UAT-09 | 오류 요청 ID로 운영 로그 조회 | 본문·토큰 없이 사건 추적 가능 | 자동 E2E 및 로컬 API 로그 확인 통과 |

## 3. 종료 기준

- 모든 필수 시나리오 통과
- 치명적/높음 결함 0건
- 보통 결함은 책임자와 수정 예정일 또는 승인된 출시 예외가 기록됨
- 제품 책임자, 운영 책임자, 보안/개인정보 책임자의 승인 기록 완료
