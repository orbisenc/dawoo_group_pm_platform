# PROJECT HUB 제품 요구사항 정의서

## 1. 문서 정보

- 제품명: PROJECT HUB
- 제품 유형: 건설 개발사업 참여자를 위한 웹 기반 프로젝트 협업 플랫폼
- 문서 상태: MVP 기준 초안
- 작성일: 2026-10-28
- 기본 언어: 한국어

## 2. 제품 비전

건설 개발사업에는 시행사, PM, 설계사, 시공사, 감리, 금융기관, 인허가 및 계약 담당자가 동시에 참여한다. 그러나 이슈, 도면, 사진, 일정, 의사결정과 승인 이력이 이메일·메신저·개별 저장소에 흩어져 있어 최신 정보와 책임 소재를 확인하기 어렵다.

PROJECT HUB는 프로젝트별 참여자와 자료를 한 공간에 모으고, 이슈에서 파일·일정·결재로 이어지는 업무 맥락을 보존한다. 사용자는 자신에게 허용된 프로젝트와 정보만 확인하며, 프로젝트 관리자는 참여자와 권한을 통제한다.

## 3. 목표와 성공 기준

### 3.1 MVP 목표

1. 프로젝트를 생성하고 외부 조직의 사용자를 초대할 수 있다.
2. 참여자가 이슈를 게시하고 댓글·첨부파일로 협업할 수 있다.
3. 프로젝트 파일을 폴더 구조로 공유하고 버전을 관리할 수 있다.
4. 주요 일정과 프로젝트 이벤트를 캘린더에서 확인할 수 있다.
5. 준비된 샘플 3D 건물 모델을 웹에서 탐색할 수 있다.
6. 문서를 상신하고 지정된 결재자가 승인 또는 반려할 수 있다.
7. 역할과 프로젝트 멤버십에 따라 데이터 접근을 제한할 수 있다.
8. 통합 대시보드에서 사용자가 참여 중인 프로젝트의 현황을 파악할 수 있다.

### 3.2 정량 성공 지표

- 초대된 사용자의 프로젝트 가입 완료율 80% 이상
- 주간 활성 프로젝트 중 이슈 또는 댓글이 생성된 프로젝트 비율 60% 이상
- 이슈 상세 화면 진입 후 댓글 또는 상태 변경 완료율 40% 이상
- 파일 업로드 성공률 99% 이상(사용자 취소 제외)
- 승인 요청 생성부터 최종 처리까지의 중간값 추적 가능
- 권한 회귀 테스트 통과율 100%
- 핵심 API의 서버 오류율 1% 미만

초기 운영 데이터가 쌓이기 전에는 지표의 절대값보다 이벤트 수집의 정확성과 추세를 우선한다.

## 4. 사용자와 역할

| 사용자군 | 주요 목적 | 대표 업무 |
| --- | --- | --- |
| 시행사 | 사업 전반의 의사결정과 진행 현황 파악 | 프로젝트 개설, 주요 이슈 확인, 결재 |
| 개발사업 PM | 참여자·일정·이슈의 통합 관리 | 멤버 초대, 이슈 배정, 일정 조율, 보고 |
| 설계사 | 설계 자료 공유와 질의 대응 | 도면·모델 공유, 설계 이슈 답변 |
| 시공사 | 시공 관련 이슈·현장 자료 협업 | 현장 사진 업로드, 공정 이슈 처리 |
| 감리 | 검토 의견과 승인 근거 기록 | 자료 검토, 댓글, 결재 |
| 금융기관 | 제한된 사업·재무 정보 확인 | 진행 현황·승인 문서 열람 |

| 계약 담당자 | 계약 문서와 승인 절차 관리 | 계약 파일 관리, 결재 상신 |

시스템 권한은 직군명이 아니라 `조직 역할 + 프로젝트 역할 + 리소스별 예외 권한`으로 계산한다. 상세 규칙은 [PERMISSIONS.md](./PERMISSIONS.md)를 따른다.

## 5. 핵심 사용자 여정

### 5.1 프로젝트 개설과 참여

1. 조직 관리자가 조직을 생성하거나 기존 조직을 선택한다.
2. 프로젝트 관리자가 프로젝트 이름, 기간, 설명을 입력한다.
3. 이메일과 프로젝트 역할로 참여자를 초대한다.
4. 초대 수락 후 사용자는 프로젝트 홈과 허용된 메뉴를 본다.

### 5.2 이슈 협업

1. 사용자가 제목, 본문, 분류, 중요도, 담당자, 마감일을 입력한다.
2. 파일 또는 사진을 첨부하고 이슈를 게시한다.
3. 참여자가 댓글과 첨부파일을 추가한다.
4. 담당자가 상태를 `등록 → 진행 중 → 검토 중 → 완료`로 변경한다.
5. 변경 내역과 주요 알림이 기록된다.

### 5.3 공유 파일 관리

1. 권한이 있는 사용자가 폴더를 만들거나 파일을 업로드한다.
2. 서버가 S3 호환 저장소의 사전 서명 URL을 발급한다.
3. 클라이언트가 저장소로 직접 업로드하고 완료를 확정한다.
4. 같은 파일의 새 버전을 올리면 버전 이력이 유지된다.
5. 사용자는 폴더 탐색, 검색, 미리보기 또는 다운로드를 수행한다.

### 5.4 기본 전자결재

1. 작성자가 제목, 내용, 관련 프로젝트, 첨부파일과 결재자를 지정한다.
2. 임시 저장 후 상신하면 대상 파일 버전·SHA-256 해시와 문서·결재선이 잠긴다.
3. 결재자는 순차적으로 승인하거나 사유를 입력해 반려한다.
4. 모든 단계가 승인되면 `승인 완료`, 반려 시 `반려`로 종료된다.
5. 반려된 안건은 수정 후 새 리비전으로 재상신하며 이전 리비전은 보존한다.
6. 상신, 승인, 반려, 회수 이력은 감사 로그에 남는다.

## 6. MVP 기능 요구사항

### F-01 인증과 계정

- 이메일과 비밀번호로 로그인·로그아웃할 수 있다.
- 이메일 초대를 통해 계정을 만들고 프로젝트에 참여할 수 있다.
- 비밀번호는 안전한 단방향 해시로 저장한다.
- 계정 상태는 `초대됨`, `활성`, `정지`를 지원한다.
- MVP에서는 소셜 로그인과 SSO를 제외한다.

### F-02 조직·프로젝트·협업 그룹

- 한 사용자는 여러 조직 및 프로젝트에 참여할 수 있다.
- 프로젝트는 이름, 코드, 설명, 기간, 상태, 대표 이미지를 가진다.
- 프로젝트 상태는 `준비`, `진행`, `보류`, `완료`, `보관`을 지원한다.
- 프로젝트 관리자는 멤버 초대, 역할 변경, 비활성화를 수행한다.
- 프로젝트 홈에 최근 이슈, 예정 일정, 최근 파일, 대기 결재를 표시한다.

### F-03 블로그형 이슈 게시판과 댓글

- 목록은 카드 또는 피드 형태로 제목, 요약, 작성자, 담당자, 상태, 중요도, 댓글 수, 첨부 수를 표시한다.
- 본문은 제한된 서식 편집을 지원하며 저장 시 안전하게 정제한다.
- 분류, 상태, 중요도, 담당자, 작성자, 기간으로 필터링할 수 있다.
- 댓글 작성·수정·삭제와 파일 첨부를 지원한다.
- 작성자와 프로젝트 관리자는 이슈를 수정할 수 있다.
- 이슈와 댓글은 소프트 삭제하며 감사 이력을 보존한다.
- MVP 알림은 앱 내 알림으로 제공하고 이메일은 초대·중요 알림부터 적용한다.

### F-04 파일·사진 첨부

- 이슈, 댓글, 결재 문서에 파일을 연결할 수 있다.
- 이미지 파일은 썸네일과 기본 미리보기를 제공한다.
- 허용 확장자와 MIME 유형을 서버에서 함께 검증한다.
- 기본 업로드 제한은 파일당 100MB로 두고 환경설정으로 변경 가능하게 한다.
- 업로드 중 진행률과 실패 사유를 한국어로 표시한다.
- 업로드 완료 전 생성된 임시 객체는 정기 정리 대상으로 표시한다.

### F-05 공유 파일함

- 프로젝트별 루트 폴더와 하위 폴더를 제공한다.
- 폴더 생성, 이름 변경, 이동, 소프트 삭제를 지원한다.
- 파일 업로드, 다운로드, 이름 변경, 이동, 새 버전 업로드를 지원한다.
- 목록과 격자 보기, 경로 탐색, 이름 검색, 정렬을 제공한다.
- 파일 버전마다 업로더, 크기, 체크섬, 생성시각을 기록한다.
- 폴더 및 파일은 프로젝트 권한을 상속하며, 제한 폴더는 별도 접근 목록을 가질 수 있다.
- MVP에서는 실시간 공동 편집, 외부 공개 링크, 문서 내 검색을 제외한다.

### F-06 프로젝트 캘린더

- 월간 캘린더와 다가오는 일정 목록을 제공한다.
- 일정은 제목, 설명, 시작·종료시각, 종일 여부, 분류, 담당자, 장소를 가진다.
- 일정 분류는 `회의`, `설계`, `인허가`, `계약`, `공정`, `결재`, `기타`를 기본 제공한다.
- 프로젝트 멤버는 권한에 따라 일정을 생성·수정·삭제한다.
- MVP에서는 반복 일정, 외부 캘린더 동기화, 자원 예약을 제외한다.

### F-07 샘플 3D 건물 뷰어

- 외부 다운로드 없이 시스템 코드가 자체 생성한 건축물 데모 모델을 브라우저에서 표시한다.
- 회전, 이동, 확대·축소, 화면 맞춤, 기본 시점 복귀를 지원한다.
- 데모 객체 선택·강조, 층별 표시, 객체별 샘플 속성과 관련 이슈 생성·보기를 지원한다.
- 화면에 실제 BIM 연동 전 데모 모델임을 명확히 표시하고 모델 공급 계층은 `ViewerAdapter`로 분리한다.
- 모델 로딩과 오류 상태를 한국어로 안내한다.
- 데스크톱을 우선하되 모바일에서는 기본 탐색이 가능해야 한다.
- MVP에서는 사용자 모델 업로드, 실제 IFC 속성 파싱, DWG 변환, 전체 BIM 속성 트리, 단면, 측정, 마크업을 제외한다.

### F-08 기본 전자결재

- 결재 문서는 `임시 저장`, `결재 중`, `승인 완료`, `반려`, `회수` 상태를 가진다.
- 한 명 이상의 결재자를 순서대로 지정한다.
- 현재 순번의 결재자만 승인 또는 반려할 수 있다.
- 반려 의견은 필수이고 승인 의견은 선택이다.
- 작성자는 첫 승인 전 결재를 회수할 수 있다.
- 결재 중인 제목, 본문, 첨부, 결재선은 변경할 수 없다.
- 상신 시 선택한 파일 버전, 객체 키, SHA-256 해시를 불변 리비전에 고정한다.
- 반려·회수 후 재상신하면 새 리비전을 생성하고 이전 자료와 이력을 유지한다.
- 위임, 병렬 결재, 합의, 대결, 전자서명 인증은 MVP에서 제외한다.

### F-09 통합 대시보드

- 참여 프로젝트 수, 진행 중 이슈, 내 담당 이슈, 예정 일정, 결재 대기 수를 표시한다.
- 사용자가 접근 가능한 프로젝트만 집계한다.
- 최근 활동과 바로가기 영역을 제공한다.
- 프로젝트별 진행 상태는 MVP에서 이슈 상태와 주요 일정 기반의 요약으로 표시한다.
- 프로젝트·이슈·일정·공유 문서·결재를 한 번에 찾는 통합 검색을 제공한다.
- 대시보드와 검색 결과는 프로젝트, 비공개 그룹, 제한 폴더 접근 권한을 동일하게 적용한다.
- 실제 데이터가 없으면 샘플을 대신 표시하지 않고 다음 행동을 포함한 빈 상태를 제공한다.

### F-10 알림과 활동 기록

- 담당자 지정, 댓글, 멘션, 일정 변경, 결재 요청·처리 시 앱 내 알림을 생성한다.
- 알림 읽음 처리를 지원한다.
- 주요 보안·권한·결재·파일 이벤트는 감사 로그로 별도 기록한다.

## 7. 공통 UI/UX 요구사항

- 사용자에게 보이는 메뉴, 버튼, 상태, 오류, 빈 화면, 도움말은 모두 한국어로 작성한다.
- 날짜는 기본적으로 `YYYY. MM. DD.` 형식을 사용하고 시각은 한국 시간 기준으로 표시한다.
- 데스크톱 1280px 이상을 주 사용 환경으로 하며 태블릿과 모바일에 반응형으로 대응한다.
- 키보드 탐색, 명확한 포커스 표시, 폼 레이블, 충분한 명도 대비를 제공한다.
- 삭제·회수·반려 등 영향이 큰 작업은 확인 또는 사유 입력 단계를 둔다.
- 데이터가 없는 상태에는 가능한 다음 행동을 안내한다.
- 서버 권한 판단을 UI 숨김만으로 대체하지 않는다.

## 8. 비기능 요구사항

### 8.0 기술 기준

- 웹 애플리케이션은 Next.js와 TypeScript를 기본으로 한다.
- 백엔드 API는 NestJS와 TypeScript를 기본으로 한다.
- 업무 데이터는 PostgreSQL, 캐시와 비동기 작업은 Redis를 사용한다.
- 파일과 사진, 3D 샘플 자산은 비공개 S3 호환 저장소에 보관한다.
- 초기 구현은 모듈형 모놀리스를 우선하며 세부 구조는 [ARCHITECTURE.md](./ARCHITECTURE.md)를 따른다.

### 8.1 성능

- 일반 목록·상세 API의 목표 응답시간은 p95 500ms 이하(파일 전송 제외)다.
- 주요 페이지의 초기 콘텐츠는 일반 사내 네트워크에서 3초 이내 표시를 목표로 한다.
- 목록 API는 커서 또는 페이지 기반 페이지네이션을 사용한다.
- 대용량 파일은 애플리케이션 서버를 경유하지 않고 S3 호환 저장소로 직접 전송한다.

### 8.2 보안

- 모든 API는 인증·권한을 서버에서 검증한다.
- 비밀번호와 토큰, 저장소 키는 로그와 저장소에 남기지 않는다.
- 업로드 파일명은 표시용 원본명과 저장용 객체 키를 분리한다.
- HTML 입력은 허용 목록 방식으로 정제하고 출력 시 이스케이프한다.
- 로그인, 초대, 권한 변경, 파일 접근, 결재 이벤트를 감사 가능하게 기록한다.
- 운영 환경은 TLS를 강제하고 쿠키 사용 시 `HttpOnly`, `Secure`, 적절한 `SameSite`를 적용한다.

### 8.3 신뢰성과 복구

- PostgreSQL 데이터는 정기 백업과 복구 검증 절차를 가진다.
- S3 객체는 DB 메타데이터와 상태를 대조할 수 있어야 한다.
- 비동기 작업은 멱등 키와 재시도 정책을 사용한다.
- 소프트 삭제된 핵심 데이터는 보존 기간 내 관리자 복구가 가능하도록 설계한다.

### 8.4 관측성

- 요청 ID, 사용자 ID, 프로젝트 ID를 구조화 로그에 포함하되 개인정보 본문은 기록하지 않는다.
- API 오류율, 응답시간, 큐 실패, 저장소 오류, DB 연결 상태를 측정한다.
- 감사 로그와 운영 로그를 분리한다.

## 11. 수용 기준

MVP 완료는 다음 시나리오가 통합 테스트와 브라우저 E2E 테스트를 모두 통과할 때로 정의한다.

1. 관리자가 프로젝트를 만들고 다른 조직의 사용자를 초대한다.
2. 초대 사용자가 로그인해 허용된 프로젝트만 확인한다.
3. 사용자가 사진을 첨부한 이슈를 등록하고 다른 사용자가 댓글을 남긴다.
4. 사용자가 공유 파일함에 폴더를 만들고 파일과 새 버전을 올린다.
5. 사용자가 프로젝트 일정을 등록하고 대시보드에서 확인한다.
6. 사용자가 샘플 3D 모델을 열어 회전·이동·확대한다.
7. 작성자가 결재를 상신하고 결재자가 승인 또는 반려한다.
8. 권한이 없는 사용자의 직접 URL 및 API 접근이 거부된다.
9. 주요 행위가 감사 로그에 남는다.

## 12. 미결정 사항

- 개인정보·문서 보존 및 국내 규제 준수 범위
- 프로젝트 진행률의 공식 산정 방식
