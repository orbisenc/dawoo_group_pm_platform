# 장애 대응 절차

## 1. 등급

- `SEV-1`: 전체 로그인/핵심 업무 불가, 데이터 손실·유출 의심, 프로젝트 간 접근 가능성
- `SEV-2`: 핵심 기능 일부 불가, 반복적인 5xx, 백업·큐·외부 연동의 지속 실패
- `SEV-3`: 우회 가능한 부분 장애나 성능 저하

## 2. 역할

- 상황 책임자: 등급 결정, 의사결정과 공지 승인
- 기술 대응자: 로그·메트릭 분석, 완화와 복구
- 기록 담당자: 시각별 조치, 요청 ID, 배포 버전과 검증 결과 기록
- 사용자 연락 담당자: 영향 범위와 다음 업데이트 시각 안내

한 사람이 여러 역할을 맡을 수 있으나 SEV-1의 데이터 복구·권한 변경은 다른 관리자의 확인을 받는다.

## 3. 최초 15분

1. 사건 번호와 시작 시각을 기록한다.
2. `/health`, `/health/ready`, 메트릭, 최근 배포와 5xx 로그를 확인한다.
3. 영향받는 기능·프로젝트·사용자 범위를 확인하되 운영 데이터 내용을 복사하지 않는다.
4. 권한 우회나 유출 의심 시 외부 접근과 해당 자격증명을 우선 차단한다.
5. 최근 배포가 원인일 가능성이 높으면 [롤백 절차](./DEPLOYMENT.md#5-롤백)를 실행한다.

## 4. 복구 확인

- 생존·준비 상태가 3회 연속 정상
- 대표 로그인, 프로젝트 접근, 이슈 조회, 파일 권한, 결재 조회 스모크 테스트 통과
- 15분 동안 5xx와 p95가 정상 범위
- 데이터 사건이면 DB 레코드와 객체 메타데이터 대조 완료

## 5. 사후 조치

SEV-1/2는 2영업일 안에 원인, 탐지, 영향, 시간대별 조치, 재발 방지 담당자와 완료일을 기록한다. 개인정보 침해가 의심되면 내부 개인정보 담당자에게 즉시 알리고 관계 법령과 계약에 따른 통지 필요성을 검토한다.
